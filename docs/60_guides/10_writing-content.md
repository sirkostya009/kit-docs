# Writing content

Pages are plain markdown processed by [unified](https://unifiedjs.com) with [remark-gfm](https://github.com/remarkjs/remark-gfm) enabled. Anything you can write in GitHub-flavored markdown works here — tables, task lists, footnotes, autolinks.

See the [markdown showcase](/markdown-showcase.html) for a live rendering of every feature.

## File layout

Drop files into `docs/` and they appear in the sidebar:

```
docs/
  getting-started.md      → /getting-started.html
  guides/
    installation.md       → /guides/installation.html
  advanced/
    sub-routes.md         → /advanced/sub-routes.html
```

Top-level files render as flat entries. Files in subdirectories group under the directory name. See [sub-routes](/advanced/sub-routes.html) for the full mechanism.

### Sidebar order

By default, entries sort lexically by filename within each group. Prefix files or folders with `NN_` to force a specific order — the prefix is stripped from the URL slug. So `docs/01_guides/02_writing-content.md` serves at `/guides/writing-content.html` but appears between `00_` and `03_` siblings in the sidebar.

```
docs/
  00_getting-started.md      → /getting-started.html
  01_guides/
    00_installation.md       → /guides/installation.html
    10_writing-content.md    → /guides/writing-content.html
  02_advanced/
    sub-routes.md            → /advanced/sub-routes.html
```

Mix prefixed and unprefixed files freely; unprefixed ones sort after the digit range.

## Headings

Use a single `# h1` per page — the page title from frontmatter is not auto-rendered into the body. After that, only `h2` and `h3` appear in the on-this-page nav.

```markdown
# Page title

## Section

### Subsection

#### Detail (excluded from the right nav)
```

Anchors are generated by `rehype-slug`. The hover-revealed `#` link comes from `rehype-autolink-headings`.

## Code blocks

Fenced code blocks are highlighted by [Shiki](https://shiki.style) with dual `github-light` / `github-dark` themes — see [syntax highlighting](/advanced/syntax-highlighting.html) for the language list and how to add a new one.

````markdown
```typescript
const greet = (name: string) => `hello, ${name}`;
```
````

### Inline code

Wrap with single backticks: `const x = 1`. Append a `{:lang}` annotation to syntax-highlight the snippet — `` `fetch(url){:js}` `` renders as `fetch(url){:js}`.

### Highlighting lines

Append a line range to the language tag:

````markdown
```ts {2-4}
function noop() {}
function add(a: number, b: number) {
	return a + b;
}
function done() {}
```
````

Or annotate inline with magic comments:

````markdown
```ts
function noop() {}
function add(a: number, b: number) {
	return a + b; // [!code highlight]
}
function remove() {} // [!code --]
function added() {} // [!code ++]
```
````

### Titles

Add a `title="..."` to the meta string to render a header bar above the block:

````markdown
```ts title="src/lib/server/content.ts"
import { unified } from 'unified';
```
````

### Line numbers

Add `showLineNumbers` to the meta string to render a left gutter:

````markdown
```ts {showLineNumbers}
const a = 1;
const b = 2;
```
````

Pairs with line highlights and the `title="..."` decorator.

### Chrome

Every rendered code block gets:

- a language badge in the top-right corner (uppercase, derived from the fence language)
- a copy-to-clipboard button revealed on hover
- a wrap toggle button revealed on hover — flips long lines from horizontal scroll to soft wrap

Nothing to enable, nothing to opt out of.

## Callouts

Use directive syntax for first-class callouts. Six flavors are recognized: `note`, `info`, `tip`, `warning`, `caution`, `danger`.

```markdown
:::tip
This is a tip. Markdown inside works — **bold**, `code`, [links](/).
:::

:::warning[Custom heading]
Override the default heading by putting the label in square brackets after the directive name.
:::
```

:::note
Plain informational call-out.
:::

:::tip
Forward-looking advice — good for "you can also..." asides.
:::

:::warning
Highlight a footgun before the reader hits it.
:::

:::danger
Reserve for irreversible actions (data loss, security risk).
:::

Blockquotes still work for simpler asides and cycle through colors at deeper nesting levels.

## Tables

GFM tables work out of the box, with alignment markers:

```markdown
| left | center | right |
| :--- | :----: | ----: |
| one  |  two   | three |
```

Long cell content wraps automatically. The container is rounded and bordered via the prose styles in `[...slug].html/+page.svelte`.

## Links

Internal links should use the `.html` suffix:

```markdown
See [installation](/guides/installation.html).
```

External links open in the same tab unless you add `{target="_blank"}` (when you enable [remark-directive](https://github.com/remarkjs/remark-directive)). Autolinks work for bare URLs.

## Images

Drop images in `static/` and reference them with an absolute path:

```markdown
![QA Sphere logo](/img/logo.png)
```

For images alongside the markdown source, use a relative path — Vite resolves them at build time:

```markdown
![diagram](./diagram.svg)
```

## Footnotes

`remark-gfm` ships with footnotes:

```markdown
Some claim.[^source]

[^source]: Citation here. Supports **formatting** and `code`.
```

## Frontmatter

Every page should have a `title` and `description` at minimum. The full field reference is on the [frontmatter page](/frontmatter.html).

## Editor setup

Any editor with markdown highlighting works. For best results:

- **VS Code**: install `dbankier.vscode-quick-select` and `yzhang.markdown-all-in-one`.
- **Neovim**: enable `markdown` + `mdx` filetypes in [nvim-treesitter](https://github.com/nvim-treesitter/nvim-treesitter).
- **Zed**: built-in markdown LSP via `markdown-oxide`.

Live preview is just `pnpm dev` — pages hot-reload as you save.
