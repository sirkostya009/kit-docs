# Writing content

Pages are plain markdown processed by [unified](https://unifiedjs.com) with [remark-gfm](https://github.com/remarkjs/remark-gfm) enabled. Anything you can write in GitHub-flavored markdown works here — tables, task lists, footnotes, autolinks.

See the [markdown showcase](/markdown-showcase.html) for a live rendering of every feature.

## File layout

Drop files into `docs/` and they appear in the sidebar:

```
docs/
  getting-started.md      → /getting-started.html
  guides/
    installation.md       → /guides/installation.html
  advanced/
    sub-routes.md         → /advanced/sub-routes.html
```

Top-level files render as flat entries. Files in subdirectories group under the directory name. See [sub-routes](/advanced/sub-routes.html) for the full mechanism.

## Headings

Use a single `# h1` per page — the page title from frontmatter is not auto-rendered into the body. After that, only `h2` and `h3` appear in the on-this-page nav.

```markdown
# Page title

## Section

### Subsection

#### Detail (excluded from the right nav)
```

Anchors are generated by `rehype-slug`. The hover-revealed `#` link comes from `rehype-autolink-headings`.

## Code blocks

Fenced code blocks are highlighted by [Shiki](https://shiki.style) with dual `github-light` / `github-dark` themes — see [syntax highlighting](/advanced/syntax-highlighting.html) for the language list and how to add a new one.

````markdown
```typescript
const greet = (name: string) => `hello, ${name}`;
```
````

### Inline code

Wrap with single backticks: `const x = 1`.

### Highlighting lines

Append a line range:

````markdown
```ts {2-4}
function noop() {}
function add(a: number, b: number) {
	return a + b;
}
function done() {}
```
````

> **Note:** Line highlighting requires the `transformerNotationHighlight` Shiki transformer. It's wired up but not yet styled — see [the open task](https://github.com/sirkostya009/kit-docs/issues).

## Callouts

Use blockquotes. The starter styles them with a colored left border based on the leading bold word:

```markdown
> **Note:** Plain informational call-out.

> **Tip:** Forward-looking advice.

> **Warning:** Highlight a footgun.
```

Nested blockquotes cycle through colors — yellow, red, orange, green — up to eight levels deep. Useful for indicating severity in postmortem-style docs.

## Tables

GFM tables work out of the box, with alignment markers:

```markdown
| left | center | right |
| :--- | :----: | ----: |
| one  |  two   | three |
```

Long cell content wraps automatically. The container is rounded and bordered via the prose styles in `[...slug].html/+page.svelte`.

## Links

Internal links should use the `.html` suffix:

```markdown
See [installation](/guides/installation.html).
```

External links open in the same tab unless you add `{target="_blank"}` (when you enable [remark-directive](https://github.com/remarkjs/remark-directive)). Autolinks work for bare URLs.

## Images

Drop images in `static/` and reference them with an absolute path:

```markdown
![QA Sphere logo](/img/logo.png)
```

For images alongside the markdown source, use a relative path — Vite resolves them at build time:

```markdown
![diagram](./diagram.svg)
```

## Footnotes

`remark-gfm` ships with footnotes:

```markdown
Some claim.[^source]

[^source]: Citation here. Supports **formatting** and `code`.
```

## Frontmatter

Every page should have a `title` and `description` at minimum. The full field reference is on the [frontmatter page](/frontmatter.html).

## Editor setup

Any editor with markdown highlighting works. For best results:

- **VS Code**: install `dbankier.vscode-quick-select` and `yzhang.markdown-all-in-one`.
- **Neovim**: enable `markdown` + `mdx` filetypes in [nvim-treesitter](https://github.com/nvim-treesitter/nvim-treesitter).
- **Zed**: built-in markdown LSP via `markdown-oxide`.

Live preview is just `pnpm dev` — pages hot-reload as you save.
